# ZAK 프로토타입 마일스톤

원칙: 각 마일스톤은 **하나의 리스크만 검증**한다. 완료 기준을 만족하면 다음으로 넘어가고, 재미가 없거나 기술이 막히면 그 시점에 방향을 수정한다. 퍼즐/전투는 지도와 분리해 별도 씬에서 검증한다.

## M0 — 지도 + 줌 스케일감 (진행 중)
- 부산 상가업소 CSV를 업종별 색점으로 표시
- 카메라: 스크롤 줌(커서 기준) + Q/E 줌, WASD/드래그 팬 (팬 속도는 줌 폭 비례)
- **완료 기준**: 6단계 줌을 오가며 "관망의 느낌"이 있는지 판단. 10km 뷰에서 부산 도시 구조가 데이터 밀도만으로 읽히는지 확인
- 리스크: 없음 (스크립트 완성 상태, 데이터 준비만 필요)

## M1 — 네비게이션
- OSM 도로 데이터 파싱 → 노드 그래프 구축
- A* 경로 탐색, 지도 클릭 → 경로 라인 표시 → 점(유닛)이 경로 따라 이동
- **완료 기준**: 부산 임의 두 지점 클릭 시 실제 도로를 따르는 그럴듯한 경로가 1초 내 표시되고 유닛이 이동
- 리스크: 이 프로젝트의 최대 신규 기술. 그래프 규모(부산 도로 노드 수만 개)와 탐색 성능

## M2 — 건물 비주얼
- GIS건물통합정보(또는 OSM) footprint + 층수 로드, extrude 메시 생성
- 청크 결합, 줌아웃 시 평면 LOD 전환
- 낮/밤 토글 + emissive 창문 (간단 버전)
- **완료 기준**: 2~3단계 줌에서 화면 가장자리 고층이 기울어 보이고, 프레임이 유지되며, 밤 뷰에서 "야경 감상" 가치가 있는지 판단

## M3 — 루팅
- 건물 클릭 → 층별 상점 팝업 UI (데이터 기반, 모듈식)
- 업종 소분류 → 아이템 풀 매핑 테이블 (스프레드시트로 관리)
- 간단 인벤토리
- **완료 기준**: 아무 건물이나 들어가서 "이 건물엔 뭐가 있을까" 기대감이 생기는지. 긴장 요소는 M5로 미룸
- 리스크: 기술 리스크 낮음. 재미 리스크(테이블 밸런스)가 본체

## M4 — 전투/퍼즐 프로토 (별도 씬)
- 언더테일식 회피 전투 1종: 패턴 2~3개, 싸움/회피 선택, 스태미너
- 퍼즐 시스템 1종: POI 데이터로 파라미터화 가능한 형태
- **완료 기준**: 지도 없이 그 자체로 3분간 재밌는지. 아니면 여기서 갈아엎어도 손실 최소

## M5 — 루프 결합
- 관망(신호) → 이동(M1) → 현장(M3/M4) → 귀환을 하나의 세션으로
- 소음/시간압박 등 루팅 긴장 메커니즘 1차 구현
- 스태미너/자원이 루프를 관통하도록
- **완료 기준**: 15분 플레이 세션이 성립하고, "다음 신호로 갈까"가 스스로 궁금해지는지

## M6 — 확장 구조 검증
- 맵 해금, 거점 + 동료 원거리 지원 (SLG 요소)
- 4~6단계 줌의 구역 집계 시뮬레이션 (개별↔집계 전환)
- (선택) 비동기 멀티 데이터 구조 설계만
- **완료 기준**: 부산 → 타 도시 확장이 데이터 교체만으로 되는지
