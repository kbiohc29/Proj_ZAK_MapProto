# 개발 환경 가이드 (git 왕초보 + 클로드 코드)

## 1. git — 개념 한 줄

git은 프로젝트의 **세이브 포인트 시스템**이다. 커밋 = 세이브. 망하면 이전 세이브로 돌아갈 수 있고, 뭐가 언제 바뀌었는지 기록이 남는다. 1인 개발에서 특히 AI에게 코드를 맡길 때는 필수 — AI가 뭔가 망가뜨려도 커밋 단위로 되돌리면 되기 때문.

## 2. 최초 1회 세팅 (10분)

터미널(Windows: PowerShell 또는 클로드 코드 쓰는 그 터미널)에서:

```bash
# 0) git 설치 확인 — 버전이 나오면 설치돼 있는 것
git --version

# 1) 프로젝트 폴더로 이동 (경로는 본인 위치로)
cd C:\경로\Proj_ZAK_MapProto

# 2) 이 폴더를 git 저장소로 만들기 (한 번만)
git init

# 3) 내 정보 등록 (컴퓨터당 한 번만, 이뮨 프로젝트 때 했다면 생략)
git config --global user.name "Keb"
git config --global user.email "본인이메일"
```

그다음 이 폴더에 있는 `.gitignore` 파일을 프로젝트 루트에 넣는다 (이미 포함해뒀음).
유니티는 Library, Temp 등 수 GB의 재생성 가능한 폴더를 만드는데, .gitignore가 그것들을 세이브 대상에서 제외해준다. **이 파일이 없으면 저장소가 터지므로 첫 커밋 전에 반드시 넣을 것.**

```bash
# 4) 첫 세이브
git add .                      # 바뀐 것 전부 스테이징(세이브 후보 등록)
git commit -m "프로젝트 초기 세팅"   # 세이브 확정
```

## 3. 일상 루틴 (외울 건 이게 전부)

```bash
git status                  # 뭐가 바뀌었나 확인
git add .                   # 전부 등록
git commit -m "M0 카메라 조작 추가"   # 세이브
git log --oneline           # 세이브 목록 보기
```

- 커밋 주기: 작업 세션이 끝날 때마다, 또는 "지금 상태 잃으면 아까운" 순간마다
- 커밋 메시지: 한국어로 편하게. "뭘 했는지" 한 줄이면 충분
- **꿀팁: 클로드 코드에게 "커밋해줘"라고 하면 알아서 status 보고 메시지 지어서 커밋한다.** 초보 단계에선 이게 제일 편한 방법

## 4. GitHub 백업 (선택, 나중에 해도 됨)

로컬 커밋만으로도 프로토는 충분하다. 컴퓨터가 죽을 때를 대비한 백업이 필요해지면:
1. github.com에서 New repository (Private) 생성, README 등 추가 옵션은 전부 체크 해제
2. GitHub가 보여주는 "push an existing repository" 명령 2줄을 복사해서 터미널에 붙여넣기
3. 이후엔 `git push` 한 줄로 백업

## 5. 클로드 코드 — 다시 시작하기

```bash
cd C:\경로\Proj_ZAK_MapProto   # 반드시 프로젝트 루트에서 실행
claude
```

- 실행하면 대화형 세션이 열린다. 자연어로 지시하면 파일을 읽고/수정하고/명령을 실행하며, 수정 전에 승인을 물어본다
- **CLAUDE.md는 프로젝트 루트에 있으면 세션 시작 시 자동으로 읽힌다.** 별도 연결 작업 불필요
- docs/ 연계: CLAUDE.md에 "docs/design.md 참고"라고 적혀 있으므로(이미 적어둠) 클로드가 필요할 때 알아서 읽는다. 특정 작업 때 확실히 읽히고 싶으면 대화에서 "docs/milestones.md 보고 M1 시작하자"처럼 직접 언급
- 유용한 명령: `/memory` (현재 읽힌 메모리 파일 확인), `/init` (CLAUDE.md 자동 생성 — 우리는 이미 만들었으니 불필요)
- 세션 첫 지시 예시: "CLAUDE.md랑 docs 읽고, M0 상태 확인한 다음 뭘 하면 될지 알려줘"

공식 문서: https://docs.claude.com/en/docs/claude-code/overview
