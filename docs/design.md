# ZAK — 기획 정리 (프로토타입 기준)

> 지금까지의 아이디에이션을 정리한 살아있는 문서. 확정/유력/미결을 구분해서 관리한다.

## 1. 컨셉 (확정)

대한민국 실제 지도 위에서 벌어지는 좀비 아포칼립스. 플레이어는 지도를 관망하며 도움이 필요한 곳을 찾고, 이동해서 개입한다(루팅/퍼즐/전투). 익숙한 현실(내 동네, 내 도시)이 그대로 게임 무대가 되는 것이 핵심 정서.

- 참조점: 미니 모토웨이(미니멀 조작·미학), 전염병 주식회사(집계 시뮬레이션), 언더테일(전투), 배틀그라운드(루팅 긴장감)
- 차별점: 기존 실지도 게임(Infection Free Zone 등)과 달리 유닛 마이크로가 아닌 관망→발견→개입 루프

## 2. 데이터 소스 (확정)

| 데이터 | 출처 | 용도 |
|---|---|---|
| 상가업소 (상호·업종 247분류·층·경위도) | 공공데이터포털, 소상공인시장진흥공단 상가(상권)정보. 분기별 CSV | 루팅 콘텐츠, POI 표시, 밀도 비주얼 |
| 건물 footprint + 층수·높이 | 국토교통부 GIS건물통합정보 / V-World | 건물 3D extrude |
| 도로망 | OSM (한국 커버리지 양호) | 네비게이션 그래프 |

원칙: **데이터는 공공, 렌더링은 자체.** 네이버/카카오 지도 타일은 약관상 사용 불가이며, 스타일라이즈 자체 렌더링이 미학·성능 면에서도 유리.

## 3. 지도와 줌 (확정)

뷰 가로폭 기준 6단계. 1~3단계는 "행동하는 층"(개별 단위), 4~6단계는 "읽는 층"(집계 단위).

| 단계 | 뷰 폭 | 역할 |
|---|---|---|
| 1 | ~100m | 건물 상세 (2단계에서 건물 클릭/확대 진입) |
| 2 | ~500m | 게임 운영 |
| 3 | ~2km | 게임 운영 (RTS 지휘 스케일) |
| 4 | ~10km | 동 단위 상황. 전국 훑어보기에 적당하다고 체감 확인 |
| 5 | ~20km | 구 단위 상황 |
| 6 | ~100km | 시·도 단위 상황, 타 지역/플레이어 비동기 정보 열람 |

- 기술 핵심: 3단계↔4단계 경계에서 개별 시뮬레이션 ↔ 구역 집계 모델 전환 (전 지역 개별 좀비 시뮬은 불가능)
- 맵은 처음부터 다 밝히지 않고 점차 해금. 해금 수단으로 지역별 컴퓨터/관측 배치 아이디어

## 4. 비주얼 (유력)

- 건물: footprint를 층수×3m로 extrude한 심플 3D. 원근 카메라 수직 탑뷰 → 화면 가장자리 고층이 자연스럽게 기울어짐 (네이버지도의 그 느낌, 셰이더 트릭 불필요)
- 최적화: 청크 단위 메시 결합, 줌아웃 시 extrude 끄고 평면 footprint로 LOD 전환
- 낮/밤: 프로시저럴 emissive 창문으로 야경. **밤의 불빛 = 생존자 신호 = 좀비를 부르는 위험** — 비주얼과 정보 시스템이 한 몸이 되는 아껴둘 아이디어

## 5. 플레이 루프 (유력, 상세 미결)

관망(신호 발견) → 네비게이션 이동 → 현장 개입(루팅 / 퍼즐 / 전투) → 귀환·자원 활용

### 이동/네비게이션
- 실제 도로 기반, 지도앱처럼 목적지 찍으면 경로 이동
- 초반: 내가 유일한 유닛(직접 이동, 잃으면 끝) → 후반: 거점 해금, 동료들이 원거리 지원 (같은 이동 시스템, SLG로 자연 확장)
- "나"의 아바타 표시는 필수 아님 — 움직이는 것은 동료/유닛, 나는 지휘 의지로 해석 가능

### 루팅
- 건물 클릭 → 진입 → 데이터 기반 층별 상점 팝업 (모듈화 가능)
- 업종 소분류(247개) → 아이템 풀 매핑 테이블 하나로 전국 모든 건물이 루팅 스팟이 됨 (저작량이 아닌 데이터량에 비례하는 콘텐츠)
- 예: 1층 편의점 = 식품·소모품 / 3층 병원 = 구급약·나이프 / 컨테이너 = 랜덤
- 목표 감정: 배그식 쫄깃함 — 파밍 중 무방비 상태의 긴장
- 미결: 아이템 종류·활용도, 적 등장 방식. 후보 아이디어: 소음 게이지(뒤질수록 좀비 어그로), 체류 시간 압박, 진입 전 위험 신호 읽기(핏자국 등)

### 퍼즐
- 지역 상황에 어울리는 퍼즐 기믹. 재밌고 너무 어렵지 않게 (서브컬처 게임 퍼즐 경험 기반)
- 1인 개발 원칙: 수제 퍼즐 양산 금지. 퍼즐 시스템 소수 + 실제 POI 데이터로 파라미터화

### 전투 (보스전)
- 언더테일 느낌: 신박한 공격 패턴 회피
- 싸울지/피할지 유저 선택. 회피 시 스태미너 절약 → 다른 곳에 쓰는 메리트
- 미결: 플레이어 공격 방식 유지 여부. 참고: 언더테일의 선택이 강한 이유는 자원 효율이 아니라 서사적 무게 — "싸우지 않는다"에 서사를 실을 수 있는지 검토

## 6. 환경/상황 설계 원칙 (확정)

- 유저가 의미 있는 선택을 하도록 상황 조성: 사람이냐 식량이냐, 하이리스크 하이리턴
- 선택이 의미 있으려면 정보가 불완전해야 함 ("생존자 신호가 있다, 몇 명인지는 모른다")
- 이 게임의 아이디어들은 반복적으로 '정보'로 수렴함 — 정보의 획득·불완전성·신호 디자인이 정체성의 축

## 7. 멀티플레이 (유력)

- 간접 비동기 방식: 전국 공유 시뮬레이션에 각 플레이어의 지역 결과가 반영 (헬다이버즈 은하전쟁 참고)
- 실시간 협동/경쟁은 1인 개발 리스크 최대 — 보류
- 4~6단계 줌에서 타 지역 플레이어 상황 열람

## 8. BM (초기 메모)

- 이동 스킵(전용기 등) 판매는 주의 — 관망·이동이 핵심 재미라면 자기모순
- 방향: 치장(탈것 스킨), 편의(경유지 저장) 위주

## 9. 미결 질문 목록

1. 게임의 본체: 관제인가 어드벤처인가 (현재는 어드벤처 우세)
2. 루팅의 적 등장/긴장 메커니즘
3. 아이템 체계와 경제
4. 전투에서 플레이어 공격 방식
5. 밤 플레이 규칙 (숨는 시간 vs 감상 시간 vs 별도 룰)
6. 시작 위치 (랜덤/고정/라이트 게임화 여부)
7. 건물 상세정보의 추가 활용처
