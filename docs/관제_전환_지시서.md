# Proj_ZAK_MapProto — 관제(Control Room) 방향 전환 작업 지시서

## 0. 전제 (반드시 먼저 읽을 것)

- 프로젝트: `Proj_ZAK_MapProto` / Unity 3D / **Built-in Render Pipeline** (URP 아님. Volume·Renderer Feature 방식 사용 금지)
- **처음부터 다시 만들지 않는다.** 기존 지도 파이프라인은 그대로 코어로 쓴다.
- 기존 씬과 스크립트는 **삭제하지 말고 남겨둔다.** 새 씬을 추가하는 방식으로 진행.
- 작업 단위마다 **씬을 저장하고 커밋**한다. (과거 씬 미저장으로 오브젝트를 유실한 이력 있음)

---

## STEP 0. 코드 조사 및 보고 (코드 수정 금지)

작업 시작 전에 아래를 조사해서 먼저 보고할 것. 이 단계에서는 아무것도 수정하지 않는다.

조사 항목:
1. 지도 로딩 관련 스크립트 — 상가 데이터 로더, OSM 건물 extrude, 도로 렌더러의 클래스명과 파일 경로
2. 건물 오브젝트가 생성되는 방식 — 개별 GameObject인지, 병합 메시인지, 좌표 기준(15m 격자 그룹화 로직 포함)
3. 도로 기반 네비게이션(경로 탐색) 스크립트의 진입점 — "좌표 A에서 B까지 경로를 받아오는" 함수 시그니처
4. 카메라 조작(WASD 팬 / 스크롤 줌 / 줌 6단계) 스크립트
5. 야간 창문 불빛 + 블룸 처리 방식 — 포스트프로세싱 스택 버전과 세팅 위치
6. 현재 사용 중이지 않은 것으로 보이는 스크립트 목록 (`RouteTester` 등)

보고 형식: 각 항목별로 `클래스명 / 경로 / 재사용 가능 여부 / 수정 필요 지점` 한 줄씩.

## STEP 1. 비주얼 — 흰 박스 탈피 (아트 리소스 0개)

**목표: 텍스처·모델 추가 없이 "미완성 프로토타입"에서 "의도된 관제 화면"으로 인상을 바꾼다.**

기존 씬에서 바로 작업. 되돌릴 수 있게 각 항목을 개별 토글로 만들 것.

### 1-1. 풀스크린 스캔라인/그리드 오버레이 (우선순위 최상)

- Screen Space - Overlay Canvas 하나 추가, 이름 `Canvas_ControlOverlay`
- 그 아래 `RawImage`를 화면 전체(Stretch)로 배치
- 텍스처는 코드로 생성 (예: 1x4px, 3픽셀 투명 + 1픽셀 반투명 흰색), `TextureWrapMode.Repeat`, `FilterMode.Point`
- `RawImage.uvRect`의 width/height를 화면 해상도 비율로 잡아 타일링
- Inspector에서 조절 가능한 값: 라인 간격, 라인 알파(기본 0.04 정도), 온/오프 토글
- 추가로 얇은 격자(가로세로) 버전도 같은 방식으로 하나 더, 별도 토글

> 이 하나가 화면을 '세계'에서 '화면 속 화면'으로 바꾼다. 흰 박스가 미완성이 아니라 표시 방식으로 읽히게 만드는 게 목적.

### 1-2. 건물 외곽선

- 건물 바닥 폴리곤 좌표를 이미 갖고 있으므로, 그 외곽선을 **옥상 높이에** 얇은 라인으로 한 번 더 그린다
- 셰이더 신규 작성 금지. `MeshTopology.Lines`로 라인 전용 메시를 한 번에 배치 생성하는 방식 우선 검토 (건물 수가 많으므로 LineRenderer 개별 부착은 드로우콜 문제)
- 라인 색·굵기·알파를 Inspector 노출, 토글 가능하게

### 1-3. 색 규칙 정리

- 기본 팔레트를 **무채색으로** 통일 (현재 높이별 컬러는 임시 승인 상태였으므로 교체)
- 유채색은 **정보에만** 사용:
  - 화재 = 주황
  - 감염 = 보라
  - 안전/정화 완료 = 청록
  - 유닛 = 흰색 또는 노랑
- 색 정의를 `ScriptableObject` 팔레트 하나로 모아서 한 곳에서 관리

### 1-4. 거리 페이드

- `Window > Rendering > Lighting > Environment > Other Settings`의 Fog 사용
- 원경 줌 단계에서 먼 건물이 배경으로 가라앉도록 Fog 색을 배경색과 맞추고 거리 조정
- 줌 단계별로 Fog 파라미터가 달라져야 하면 카메라 줌 스크립트에서 보간

### 1-5. 검증

STEP 1 완료 시 낮/밤 각각, 줌 2단계와 5단계 스크린샷을 남길 것. 다음 단계로 넘어가기 전 승인받는다.

## STEP 2. 관제 씬 셋업

- 새 씬 `Scene_Control` 생성
- 기존 지도 시스템(상가 데이터, 건물, 도로, 카메라 조작, 야간 조명)을 프리팹으로 정리해서 배치
- **비활성화 대상**: 플레이어 캐릭터, 회피 전투, 건물 클릭 → 층별 루팅 팝업, `RouteTester`
  - 삭제가 아니라 씬에서 빼거나 비활성. 스크립트는 남긴다.
- 카메라는 고정 탑뷰. WASD 팬 + 스크롤 줌만 유지
- 실행하면 부산 지도가 뜨고 자유롭게 둘러볼 수 있는 상태까지가 이 단계의 완료 조건

## STEP 3. 재난 발생 및 확산

### 3-1. `DisasterManager`

- 일정 주기(Inspector 노출, 기본 8초)마다 화면 또는 지정 영역 내 건물 하나를 랜덤 선택해 재난 발생
- 재난 데이터: `대상 건물 ID / 종류(우선 화재만) / 심각도 0~100 / 발생 시각`

### 3-2. 심각도 진행

- 방치 시 심각도가 초당 일정량 증가 (Inspector 노출)
- 심각도에 따라 해당 건물 색이 무채색 → 주황 → 적색으로 보간
- 심각도 100 도달 시:
  - 해당 건물은 **소실** 처리 (색 고정, 진압 불가, 카운트 증가)
  - 반경 R(기본 60m) 내 건물 중 1~2개에 새 재난 발생 = 확산

### 3-3. 시각화

- 건물 색 변화 외에 지도상 마커 하나 (작은 원 + 심각도 링 게이지)
- 원경 줌에서도 보이도록 마커는 화면 공간 기준 최소 크기 보장

---

## STEP 4. 유닛 파견

### 4-1. `ResponseUnit`

- 상태: `대기 / 이동 중 / 처리 중`
- 지도상 거점(`Depot`)에서 스폰. 거점 위치는 씬에서 수동 배치 (우선 2~3개)
- 이동은 **기존 도로 네비게이션 재사용**. 직선 이동 금지 — 도로를 따라가는 것이 이 게임의 핵심 질감

### 4-2. 조작

- 좌클릭: 유닛 선택 (다중 선택은 아직 불필요)
- 우클릭: 재난 지점 지정 → 경로 계산 → 이동 시작
- **이동 중 재지정 가능** (경로 재계산). 이게 압박 상황에서의 핵심 조작이므로 반드시 동작할 것
- 유닛이 지금 어디로 가는 중인지 경로 라인을 흐리게 표시

### 4-3. 처리

- 재난 지점 도착 시 자동으로 심각도를 초당 일정량 감소
- 심각도 0 도달 시 재난 해제, 유닛은 `대기` 상태로 그 자리에 남음 (거점 복귀 강제하지 않음 — 배치가 곧 전략이 되도록)
- 유닛 여러 대가 한 지점에 붙으면 감소량 합산

---

## STEP 5. 압박 곡선과 HUD

- 시간이 지날수록 재난 발생 주기 단축 (곡선은 Inspector에서 AnimationCurve로 조절 가능하게)
- HUD 표시: 경과 시간 / 활성 재난 수 / 대기 중 유닛 수 / 소실 건물 누적
- 실패 조건: 소실 건물이 N개(기본 20) 초과 시 세션 종료 + 결과 화면
- 결과 화면에는 최소한 생존 시간과 소실 건물 수만

## 작업 규칙

- 한 STEP이 끝날 때마다 멈추고 결과를 보고한 뒤 승인을 받는다. 여러 STEP을 한 번에 진행하지 않는다.
